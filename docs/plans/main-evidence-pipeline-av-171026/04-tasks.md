## Implementation Notes (deviations)

- **Blocked:** `terraform apply` was denied by the session permission policy; `infra/evidence.tf` validates and plans (8 to add, 0 change/destroy). Run it manually, then the live scan checks in 01/02.
- GuardDuty role policy follows the official AWS template (EventBridge managed rule + bucket notification + validation object); the plan snippet lacked these and would fail plan creation. `actions` uses provider 6.x attribute syntax.
- CFDI namespace detection uses `http://www.sat.gob.mx/cfd/` (real namespace), not `/cfdi/`. DTE reads `IdDoc/TipoDTE` and `IdDoc/Folio` child elements (real schema), not attributes.
- Visual extraction module named by role (`modules/document_vision`, Textract adapter inside) per codebase-change rule 12; no forwarding service layer.
- Deterministic XML fields are overlaid on the LLM candidate (LLM supplies category); if the LLM fails, the deterministic candidate is used alone. Without a category, rule R07 sends XML bills to review.
- Evidence views assembled across modules as links (payments repo) + one `IN` query (files repo); no cross-module ORM joins (matches repo convention).
- `InboxEmailView.source_type` defaults to `email` (every inbox row is an email by construction) instead of a bill_sources lookup.
- Biome does not exist in this repo; Phase 4 ran the project's equivalents: `ruff check`/`ruff format --check`, pytest, `tsc --noEmit`, `eslint`, `next build`.
- Quality gate fixed: chat context skipped quarantined files; scan timeout reported as `attachment.scan_failed` (not malware); fake ZIP attachments blocked as unreadable; retried console runs no longer relink re-expanded members; non-PDF/XML console/chat files still work (last-resort primary); CFDI/CII non-invoice types rejected; 10-attachment cap + concurrent scans; image-only PDFs withheld from the LLM (not guardrail-screened); latin-1 XML decoding; RunTimeline retries after errors.
- Known limitations (not fixed): Textract sync `AnalyzeExpense` reads single-page PDFs only; a non-invoice XML in a ZIP still wins primary over the PDF; `/bills` cards fetch provenance per card; pre-migration file rows stay `scan_status=pending` (MinIO data, unusable); lazily-entered aioboto3 clients mirror `bedrock.py` and are never closed.
- Follow-up (user request): PDF chain is now Textract → LLM on text (pypdf text, else Textract OCR lines) → LLM with the PDF file; structured Textract fields overlay LLM output. A country-resolution step (`invoice_ingestor/origin.py`) runs after every method; `country` moved to every candidate kind; unknown XML formats yield generic currency/country/tax-id hints; the SII CLP default is recorded with a quote naming CLP. Currency is never inferred from country.
- Follow-up (user request): XML source-country registry (`invoice_ingestor/origin_registry.py`) for 21 national e-invoice standards, matched by tax-authority domain in any element namespace, structure fingerprints (EC SRI, DO e-CF, GT FEL) and UBL/CII profile markers (DIAN, SUNAT, UBL-TR, ZATCA, XRechnung, CIUS-IT); envelope unwrapping (DIAN AttachedDocument, SRI autorizacion). Stored as `DocumentOrigin` on the extraction, in the `extracted` event (`document_origin`) and as `candidate.country`.
- Follow-up (user request): country split into `payee_country` (address, LLM-visible), `issuer_tax_country` and `bank_account_country` (derived, hidden from the LLM schema; legacy `country` payloads migrate to `payee_country`). Buyer-issued documents (CL DTE 46, EC liquidación de compra, CO documento soporte) never set `issuer_tax_country`; DTE 46 / liquidación map the payee from the seller block. New `core/tax_jurisdictions.py` (tax-ID shapes + check digits, IBAN/CLABE/BIC) and rule R18 (tax ID contradicts the standard's country → review). 31 real fixtures in `backend/tests/fixtures/xml/official/` with provenance README.
