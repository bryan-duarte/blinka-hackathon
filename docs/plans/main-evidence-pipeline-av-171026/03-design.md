# Technical Design

## Architecture Decisions

1. **S3-only storage.** `ObjectStorageBackend` builds its aioboto3 session from `aws_profile`/`region` (mirroring `modules/guardrails/bedrock.py`), no endpoint override, virtual-host addressing. Bucket `blinka-evidence-<account_id>`, provisioned by Terraform. MinIO and its compose service are removed.
2. **Antivirus = GuardDuty Malware Protection for S3, gated by tag polling.** Tagging enabled at protection-plan creation (must happen **before** the first upload). After `put`, `MalwareScanService` polls `get_object_tagging` for key `GuardDutyMalwareScanStatus` (values `NO_THREATS_FOUND | THREATS_FOUND | UNSUPPORTED | ACCESS_DENIED | FAILED`). Gate lives inside `FilesService.upload` so every path (inbox attachments, console upload, ZIP members) is covered uniformly.
3. **Fail-closed on scan.** `THREATS_FOUND`, `FAILED`, `ACCESS_DENIED`, and poll timeout → file record gets `scan_status=threat|failed`, extraction is skipped, and the source is blocked with a violation (no agent run). `UNSUPPORTED` → proceed; evidence shows "Sin escaneo" in place of the AWS badge.
4. **ZIP expansion at ingestion, not extraction.** `files/archives.py::expand_zip()` (stdlib `zipfile`, bomb guards: ≤20 entries, ≤50 MB uncompressed total, compression-ratio check, member allow-list `.pdf/.xml`, basename-only names, skip `__MACOSX/`). The ZIP itself is stored as evidence (`role=archive`); members are uploaded as files (`role=primary`/`secondary`).
5. **Primary-source preference: XML > PDF.** A deterministic multi-country XML parser (`defusedxml`): a registry keyed on the root element's namespace detects the format — CFDI (MX), DTE/SII (CL), UBL (CO/PE/EU — one mapper, country read from the supplier's `cbc:IdentificationCode`), CII (EU ZUGFeRD/Factur-X). Each mapper extracts payee, tax id, amount, **ISO-4217 currency** (DTE defaults to CLP when absent) and **ISO-3166 country** with confidence 1.0. Unrecognized namespaces → LLM fallback. When both XML and PDF exist, only the XML feeds extraction; the PDF remains secondary evidence.
6. **Extraction chain** (in `invoice_ingestor`, orchestrated per file role):
   - XML primary: deterministic parse → (fail) LLM on XML text → (fail) `no_info`.
   - PDF primary: pypdf text + existing LLM path → (no text or parse failure) **Textract `AnalyzeExpense`** → (insufficient fields) `no_info`.
7. **`no_info` is a first-class terminal state.** Runner records a new `extraction_failed` event and completes the run (no decision). `_resolve_status` maps completed-without-decision-and-last-event-`extraction_failed` → `InboxEmailStatus.NO_INFO` (distinct from `no_invoice` = not a bill). Currently `InvoiceParseError` → run FAILED → inbox ERROR; that path is replaced for extraction failures.
8. **Evidence linkage = new `agent_run_files` table** (product DB). Intake writes rows with `bill_source_id`; the runner stamps `run_id` onto its source's rows at run start. `bills.bill_sources.file_id` stays untouched for back-compat but is no longer authoritative.
9. **Source values**: add `whatsapp` to `BillSourceType`; UI maps `upload` → "Consola". Column is a plain str — no migration.
10. **File access**: `GET /files/{file_id}/content` proxies S3 bytes with JWT auth + ownership check; response sets `Content-Type`, `Content-Disposition: inline`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`. Frontend fetches as blob (auth header) → `URL.createObjectURL` → new tab.
11. **Live timeline**: frontend polls the existing `GET /payments/runs/{run_id}` (`PaymentRunStatus.events`) while the email is in a pending status; no new backend endpoint.

## Patterns & Conventions

- Module layout: `modules/<name>/{models,repository,service,errors}.py` + thin client facade in `backend/clients/<name>.py` + DTOs in `backend/contracts/<name>.py`; manual DI in `backend/container.py::build_clients`.
- Alembic: **autogenerated** migrations only, two branches — new tables/columns go to the `product` branch (`alembic -n product upgrade head`). See `docs/plans/main-backend-modular-monolith-base-161026-X/06-implementation/04-persistence-alembic/spec.md`.
- AWS access: `aioboto3.Session(profile_name=..., region_name=...)` exactly as `modules/guardrails/bedrock.py` does.
- Errors: domain error classes in the module's `errors.py`, mapped to HTTP by the central handlers in `api/app.py`.
- Frontend: no component/icon libraries; class-string constants (`components/settings/styles.ts`), text glyphs, plain fetch (`lib/api.ts`), Spanish copy (`lib/labels.ts`). All UI work must follow `frontend/DESIGN.md` (cobalt accent only, 4px radii, no shadows, pills `rounded-full`, `animate-pulse` only).

## Dependencies

- **New (backend)**: `defusedxml` (XML hardening).
- Existing: `aioboto3` (S3, Textract), `pypdf`, `zipfile`/`io` (stdlib).
- **Frontend**: no new packages.
- **AWS services (all active, us-east-1)**: GuardDuty Malware Protection for S3 (free tier 1,000 req + 1 GB/month, then ~$0.09/GB + $0.215/1k requests; S3 tagging cost applies), Amazon Textract `AnalyzeExpense` (~$0.01/page sync API).

## Data Structures

### Migration (product branch) — `files` columns + `agent_run_files`

```
files:
  scan_status   String(16)  NOT NULL DEFAULT 'pending'   # pending|clean|threat|unsupported|failed|disabled
  scanned_at    DateTime    NULL

agent_run_files:
  id             UUID PK
  run_id         UUID FK agent_runs.id NULL  (indexed)   # stamped by runner
  bill_source_id UUID FK bill_sources.id NULL (indexed)  # set at intake
  file_id        UUID FK files.id (indexed)
  role           String(16)  # archive|primary|secondary
  created_at     DateTime server_default now()
```

### GuardDuty tag contract

Key `GuardDutyMalwareScanStatus`; poll `get_object_tagging(Bucket, Key)`. Value mapping: `NO_THREATS_FOUND→clean`, `THREATS_FOUND→threat`, `UNSUPPORTED→unsupported`, `ACCESS_DENIED|FAILED→failed`, no tag before timeout→timeout.
