# Persistence & Alembic (SQLAlchemy ORM)

## Overview

SQLAlchemy 2.0 declarative models for every table + Alembic migrations **always generated with the Alembic CLI autogenerate** — migrations are never written by hand. Two databases → two `DeclarativeBase` classes → two Alembic sections.

## Files to Create

- `backend/core/db/__init__.py` — re-exports `ProductBase`, `PaymentsBase`, `create_engine_and_sessionmaker`, checkpointer factories.
- `backend/core/db/base.py`:

```python
from sqlalchemy import MetaData
from sqlalchemy.orm import DeclarativeBase

NAMING_CONVENTION = {
    "ix": "ix_%(column_0_label)s",
    "uq": "uq_%(table_name)s_%(column_0_name)s",
    "ck": "ck_%(table_name)s_%(constraint_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}

class ProductBase(DeclarativeBase):        # PG-1 blinka_product
    metadata = MetaData(naming_convention=NAMING_CONVENTION)

class PaymentsBase(DeclarativeBase):       # PG-3 blinka_payments
    metadata = MetaData(naming_convention=NAMING_CONVENTION)
```

Two bases are essential: autogenerate diffs one DB against one metadata. Cross-DB FKs (e.g. nothing references between PG-1/PG-3) are forbidden.

- `backend/core/db/engine.py`:

```python
def create_engine_and_sessionmaker(dsn: str) -> tuple[AsyncEngine, async_sessionmaker[AsyncSession]]:
    engine = create_async_engine(dsn)                 # psycopg3 async driver
    return engine, async_sessionmaker(engine, expire_on_commit=False)
```

- ORM models (exact fields in 03-design.md → Data Structures):
  - `modules/auth/models.py` — `User`
  - `modules/files/models.py` — `FileRecord`
  - `modules/invoice_ingestor/models.py` — `InvoiceRecord`
  - `modules/payments/models.py` — `AgentRun`, `AgentRunEvent`
  - `modules/sessions/models.py` — `SessionRecord` (ProductBase), `SessionExecution` (PaymentsBase)
- `backend/alembic.ini` — named sections (per 03-design.md): `[product]` (url PG-1, `version_table = alembic_version_product`) and `[payments]` (url PG-3, `version_table = alembic_version_payments`), shared `script_location = alembic`.
- `backend/alembic/env.py` — picks metadata by section name; **autogenerate is the only workflow**:

```python
if config.config_ini_section == "payments":
    from modules.sessions.models import SessionExecution  # noqa: F401 (imports register tables)
    from core.db.base import PaymentsBase as target_base
else:
    import modules.auth.models, modules.files.models      # noqa: F401
    import modules.invoice_ingestor.models, modules.payments.models
    import modules.sessions.models

target_metadata = target_base.metadata
```

Run env.py offline/online templates standard. Sync engine inside env.py (`create_engine` from the same psycopg URL — strip `+asyncio` if present).

## Migration Workflow (THE rule)

```bash
cd backend
# 1. edit/create ORM models
# 2. generate (NEVER write migration files manually):
alembic -n product  revision --autogenerate -m "product schema"
alembic -n payments revision --autogenerate -m "payments schema"
# 3. review the generated file (autogenerate misses server defaults & some type changes — fix inside the generated file)
# 4. apply:
alembic -n product  upgrade head
alembic -n payments upgrade head
```

Initial base migration: create the first revision with autogenerate against empty DBs (`alembic -n product revision --autogenerate -m "create product tables"`). This first migration is still autogenerated — the rule is absolute: no hand-authored `op.create_table` files.

## Implementation Guidelines

- `Mapped[...]`/`mapped_column` style everywhere (SQLAlchemy 2.0 typed); uuid PKs `default=uuid4` (client-side); `created_at` via `server_default=func.now()`; JSONB via `sqlalchemy.dialects.postgresql.JSONB`.
- `AgentRunEvent.id` uses `Identity()` (bigint) — polling order depends on it.
- Models import ONLY `core.db.base` + sqlalchemy — never engine/session (keeps models importable by Alembic without app settings).
- Repositories use injected `async_sessionmaker[AsyncSession]` (see module specs) — no `AsyncConnectionPool` anywhere.
- LangGraph checkpoint tables (PG-2, PG-3 `checkpoint_*`) are NOT ORM models; `AsyncPostgresSaver.setup()` owns them. PG-3 hosts both `session_executions` (ours) and payment checkpoints (LangGraph's) — no conflict, different table names.
