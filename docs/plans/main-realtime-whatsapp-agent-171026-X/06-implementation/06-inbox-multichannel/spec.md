# Inbox Multichannel Implementation

## Overview

Make the inbox module channel-aware so WhatsApp documents flow through the existing pipeline. The work covers:
- connection endpoints for both WhatsApp modes;
- webhook routing;
- `source_type` derivation;
- simulated WhatsApp samples;
- a source filter on the list.

## Implementation Guidelines

### Sandbox registration (default mode)

```python
# orientative
async def register_whatsapp_sandbox(self, owner: CurrentUser, raw_phone: str) -> WhatsAppSandboxView:
    phone = normalize_phone(raw_phone)                      # from modules.whatsapp_gateway.kapso
    existing = await self._repository.get_active_sandbox_connection(phone)
    if existing is not None and existing.owner_id != owner.user_id:
        raise WhatsAppPhoneTakenError                        # InboxError → 409 "phone already registered"
    connection = existing or await self._repository.insert_connection(
        owner.user_id, MailProvider.WHATSAPP, f"sandbox:{phone}",
        mode=WhatsAppConnectionMode.SANDBOX, phone_number=phone, status=MailAccountStatus.ACTIVE)
    activation = await self._dependencies.whatsapp_gateway.create_sandbox_session(phone)
    return WhatsAppSandboxView(connection_id=connection.connection_id, phone_number=phone,
                               sandbox_number=self._kapso.sandbox_display_number,
                               activation=activation, status=connection.status)
```

- The phone is stored as `active` immediately. Kapso activation happens out of band: the user sends the code. Messages from a phone that has not been activated simply never arrive.
- Re-registering the same phone for the same owner returns a fresh activation, which makes it idempotent.

### Own-number connection (opt-in)

- `start_whatsapp_connection(owner)`:
  1. `customer_id = await repository.get_owner_kapso_customer(owner.user_id) or await gateway.ensure_customer(owner.user_id, owner.email)`.
  2. `link = await gateway.create_setup_link(customer_id)`.
  3. `insert_connection(owner_id, WHATSAPP, f"setup:{link.setup_link_id}", mode=OWN_NUMBER, external_ref=customer_id)`.
  4. Return `MailboxConnectStarted(connection_id, redirect_url=link.url)`.
- `confirm_whatsapp_connection(owner, request)`:
  1. `connection = get_owned_connection(owner, f"setup:{request.setup_link_id}")`. If it is missing, raise `MailboxConnectionMissingError`.
  2. `number = await gateway.get_phone_number(connection.external_ref, request.phone_number_id)`. This verifies the id; never trust the redirect params.
  3. `webhook_id = connection.trigger_id or await gateway.register_message_webhook(number.phone_number_id)`.
  4. `update_connection_account(connection_id, number.phone_number_id, ACTIVE, webhook_id, number.display_phone_number)`.
  5. `await repository.expire_sandbox_connections(owner.user_id)`. Own number replaces sandbox.
  6. Return the view.

### Webhook ingest

```python
# orientative
async def ingest_whatsapp_webhook(self, body: bytes, headers: Mapping[str, str]) -> None:
    for event in self._dependencies.whatsapp_gateway.parse_webhook(body, headers):
        connection = await self._whatsapp_connection_for(event)
        if connection is None:
            logger.warning("whatsapp_webhook_unknown_sender", phone_number_id=event.phone_number_id)
            continue
        owner = await self._auth.get_user(connection.owner_id)
        email_id = await self._repository.insert_email(connection.owner_id, MailProvider.WHATSAPP,
                                                       event.message_id, connection.connection_id)
        if email_id is None:
            logger.info("inbox_webhook_duplicate", message_id=event.message_id)
            continue
        await self._dependencies.notifier.item_changed(connection.owner_id, email_id, InboxEmailStatus.RECEIVED)
        self._registry.spawn(email_id, process_email(email_id, owner, event, self._dependencies))

async def _whatsapp_connection_for(self, event):
    if event.phone_number_id == self._kapso.sandbox_phone_number_id:
        return await self._repository.get_active_sandbox_connection(event.sender_phone)
    connection = await self._repository.get_connection_by_account(event.phone_number_id)
    return connection if connection and connection.status == MailAccountStatus.ACTIVE else None
```

- The webhook must answer within 10 s. Parsing and the DB insert are fast; the download happens inside `process_email`, in the background.
- Sender privacy: never log the full phone. Log `phone_number_id` only.

### Simulate

`simulate(owner, kind, channel)`:
- **email:** unchanged.
- **whatsapp:**
  1. If `kind not in WHATSAPP_SIMULATABLE_KINDS`, raise `WhatsAppSimulationUnsupportedError`.
  2. `sample = as_whatsapp_message(SIMULATED_EMAILS[kind])`, with sender `"Proveedor demo <+56900000000>"`, subject = the first attachment's filename, and body = `""`.
  3. Insert with `MailProvider.WHATSAPP` and `f"sim-{uuid4()}"`, publish `RECEIVED`, then spawn.

### Source type derivation

`_to_email_view(record, ...)` sets `source_type=SOURCE_TYPE_BY_PROVIDER[record.provider]`. `InboxEmailView.source_type` stays a field with a default, so nothing breaks.

- **Frontend contract (module 08):**
  - `POST /inbox/whatsapp/sandbox {phone_number}` → `{connection_id, phone_number, sandbox_number, activation: {activation_code, activation_link} | null, status}`

  - `POST /inbox/simulate {kind, channel}`
- **Kapso success redirect** goes to `BLINKA_KAPSO__CALLBACK_URL` (`/inbox/whatsapp/callback`) with `setup_link_id`, `status`, `phone_number_id` and `display_phone_number`. The failure redirect carries `setup_link_id` and `error_code`.
