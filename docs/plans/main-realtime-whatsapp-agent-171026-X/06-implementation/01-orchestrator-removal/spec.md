# Orchestrator Removal Implementation

## Overview

Delete the chat orchestrator and everything that only it used: chat and diagnostics routes, sessions, hello-world tools and prompts, and the agent DB. Payments triggers already call `PaymentsService` directly, so no trigger changes.

## Implementation Guidelines

- Order: delete the routers first, then the clients/services, then container wiring, contracts, prompts and DB. Run `uv run ruff check .` and `uv run python -c "import api.app"` after each step to catch dangling imports.
- `PromptsService.__init__` raises `MissingPromptsError` if any `PromptId` lacks a registry entry, so the enum and the registry must change in the same commit. Coordinate with module 02, which adds `PAYMENTS_AGENT`.
- Grep gate (must return nothing in `backend/` outside `alembic/versions` and `docs/`):
  ```bash
  rg -n "orchestrator|OrchestratorClient|hello_world|HelloWorld|MAIN_AGENT|SessionsClient|session_id|ChatStreamEvent|checkpointers\.agent|agent_database_url|pools\.agent" backend --glob '!alembic/versions/**'
  ```
- Keep `BillSourceType.CHAT` and the frontend `chat` label and badge. Legacy rows may carry them.

## Dependencies

None. This is the first module and unblocks 02.

## Integration Notes

- After this module, `PaymentRunDependencies` = `repository, ledger, bills, policy, invoice_ingestor, llm_gateway, prompts`. Module 02 adds `checkpointer` and module 03 adds `events`.
- `Checkpointers` exposes `.payments: AsyncPostgresSaver` only.
- `build_clients(settings, pools, checkpointers)` keeps its signature.
