# Technical Design

## Architecture Decisions

1. **The Terraform root stays `infra/`, flat files, no modules, local state.** New files: `network.tf`, `edge.tf`, `database.tf`, `ssm.tf`, `compute.tf`. Existing files edited: `versions.tf`, `variables.tf`, `outputs.tf`, `realtime.tf`.
2. **There are three subnet tiers across 2 AZs.**
   - public: ALB and NAT
   - private-app: ECS
   - private-db: RDS
   Only public subnets route to the IGW. Private-app routes `0.0.0.0/0` to the single NAT GW. Private-db has no default route.
3. **Security groups are chained with references to each other, never with CIDRs** (except the ALB ingress).
   - `alb`: 80 and 443 in from `0.0.0.0/0`.
   - `app`: 8000 in from `alb` only.
   - `db`: 5432 in from `app` only.
   - Egress is all open on alb and app, and none on db.
4. **One Fargate service, `blinka-backend`, with desired 1 and stop-then-start** (min 0 / max 100). Terraform creates it with `desired_count = 0` and ignores `[task_definition, desired_count]`. `deploy.sh` owns both after creation.
5. **Config: all backend env vars are SSM parameters under `/blinka/prod/<ENV_VAR_NAME>`, injected through the task definition's `secrets`.** The parameter name's last path segment equals the env var name.
   - **managed**: Terraform owns the value, e.g. DB URLs and the guardrail id.
   - **operator**: Terraform seeds a default or `assign_later` with `lifecycle { ignore_changes = [value] }`, so console edits survive `terraform apply`.
6. **Migrations run in the container entrypoint** before uvicorn starts. This is safe only because there is never more than one task.
7. **One RDS instance holds both databases.** `db_name = "blinka_product"` is created by RDS; `blinka_payments` is created by `core.db.bootstrap` on first start.
8. **Secrets are generated by Terraform with `random_password`**: DB master password, JWT secret, and demo password. Third-party API keys are `assign_later`.
9. **The AWS credentials fix:** the `aws_profile` defaults in `StorageSettings`, `TextractSettings` and `RealtimeSettings` become `None`. On ECS no `*_AWS_PROFILE` param exists, so boto uses the task role. Local `.env` keeps `=panoptico` explicitly (already in `.env.example`).

## Patterns & Conventions

- **Terraform style:** mirror `infra/evidence.tf`.
  - Use `data "aws_iam_policy_document"` and `aws_iam_role_policy`, with no inline JSON strings.
  - Resource names are snake_case and AWS names are prefixed `blinka-`. A short comment goes above a resource only when its intent isn't obvious, as in `realtime.tf`.
  - Use `data.aws_caller_identity.current` from `main.tf`; don't declare it again.
- **Reuse existing policy documents for the task role:** `data.aws_iam_policy_document.backend_evidence` (`infra/evidence.tf:146`) and `data.aws_iam_policy_document.backend_realtime_publish` (`infra/realtime.tf:118`). Attach them to the task role with `aws_iam_role_policy`.
- **Backend Python:** match `core/db/engine.py` style (small module, type hints, no comments unless needed). Use psycopg 3 (already a dependency), no new packages.
- **Shell:** `#!/usr/bin/env bash` + `set -euo pipefail`, as in vera's `fos-infra` scripts.

## Dependencies

- Terraform `>= 1.9` (existing), `hashicorp/aws >= 6.9, < 7.0` (existing), `hashicorp/archive ~> 2.7` (existing).
- **New provider:** `hashicorp/random ~> 3.7`.
- **Local tooling for deploy.sh:** AWS CLI v2, Docker with buildx, `jq`, Terraform (reads outputs).
- **Backend:** no new Python dependencies. psycopg 3.3.6 provides `psycopg.conninfo.conninfo_to_dict` / `make_conninfo` and `psycopg.sql`.

## Integration Points

- `infra/realtime.tf` `aws_lambda_function.realtime_authorizer.environment.variables.JWT_SECRET`: `var.jwt_secret` becomes `random_password.jwt_secret.result`.
- `infra/variables.tf`: remove `variable "jwt_secret"`; add `domain_name`, `api_subdomain`, `frontend_origin`, `vpc_cidr`.
- `infra/versions.tf`: add the `random` provider.
- `infra/outputs.tf`: add `api_url`, `ecr_repository_url`, `ecs_cluster_name`, `ecs_service_name`, `task_family`, `container_name`, `db_endpoint`, `ssm_prefix`, `jwt_secret` (sensitive), `demo_password` (sensitive).
- `backend/core/config.py:39,50,116`: `aws_profile: str | None = None`.
- `backend/Dockerfile`: copy `docker-entrypoint.sh` and switch CMD to ENTRYPOINT.
- `backend/core/db/bootstrap.py` (new): `python -m core.db.bootstrap`.
- `backend/alembic/env.py`: unchanged (reads `BLINKA_*_DATABASE_URL` from real env vars, which ECS injects).
- `GET /health` (`backend/api/routers/__init__.py:19`): the ALB target-group health check.
- Webhooks `POST /webhooks/mail` and `POST /webhooks/whatsapp` are reachable through the ALB at `https://api.<domain>`.

## Data Structures

### New Terraform variables (`infra/variables.tf`)
| Name | Type | Default | Purpose |
|---|---|---|---|
| `domain_name` | string | none (required) | Existing Route53 public hosted zone, e.g. `blinka.dev` |
| `api_subdomain` | string | `"api"` | API host = `${api_subdomain}.${domain_name}` |
| `frontend_origin` | string | none (required) | e.g. `https://blinka.vercel.app`, no trailing slash |
| `vpc_cidr` | string | `"10.20.0.0/16"` | VPC range |

### Locals (`infra/network.tf` or a new `infra/locals.tf`)
```hcl
locals {
  name       = "blinka"
  env        = "prod"
  ssm_prefix = "/blinka/prod"
  api_host   = "${var.api_subdomain}.${var.domain_name}"
  azs        = slice(data.aws_availability_zones.available.names, 0, 2)
  # cidrsubnet(var.vpc_cidr, 8, n): public 0-1, app 10-11, db 20-21
}
```

### IAM
**Execution role** `blinka-backend-execution`:
- Managed policy `AmazonECSTaskExecutionRolePolicy` (ECR pull and logs).
- Inline `ssm:GetParameters` on `arn:aws:ssm:${region}:${account}:parameter${local.ssm_prefix}/*`.
- No KMS statement, because SecureStrings use the AWS-managed `alias/aws/ssm` key.

**Task role** `blinka-backend-task`:
- `backend_evidence` doc (S3 objects and bucket, Textract).
- `backend_realtime_publish` doc (AppSync EventConnect and EventPublish).
- New doc `backend_guardrail`: `bedrock:ApplyGuardrail` on `aws_bedrock_guardrail.email_input_guard.guardrail_arn` and on `arn:aws:bedrock:*:${account}:guardrail-profile/us.guardrail.v1:0` (needed by the cross-region profile).
- New doc `ecs_exec`: `ssmmessages:CreateControlChannel`, `CreateDataChannel`, `OpenControlChannel`, `OpenDataChannel` on `*`.
- Trust for both roles: `ecs-tasks.amazonaws.com` with `aws:SourceAccount = account id`.
