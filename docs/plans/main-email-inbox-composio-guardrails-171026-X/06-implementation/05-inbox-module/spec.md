# Inbox Module Implementation

## Overview

The inbox module owns mailbox connections and received emails. It runs the email pipeline in the background: fetch → store as file → guardrail → payment run. It serves the inbox views, including the status derived from each run.

These snippets are orientative.

### `models.py`

Mirror `modules/files/models.py`. `InboxEmail.__table_args__ = (UniqueConstraint("provider", "external_message_id"),)`. `violations: Mapped[list] = mapped_column(JSONB, default=list)`. `body: Mapped[str] = mapped_column(Text, default="")`.

| Method | Notes |
|---|---|
| `insert_connection(owner_id, provider, connected_account_id) -> UUID` | |

### `pipeline.py`

```python
@dataclass(frozen=True)
class InboxDependencies:
    repository: InboxRepository
    files: "FilesClient"
    guardrails: "GuardrailsClient"
    payments: "PaymentsClient"
    mail_gateway: "MailGatewayClient"


async def process_email(email_id: UUID, owner: CurrentUser,
                        source: MailTriggerEvent | FetchedEmail,
                        dependencies: InboxDependencies) -> None:
    repository = dependencies.repository
    await repository.update_email(email_id, status=InboxEmailStatus.PROCESSING)
    try:
        await _analyze(email_id, owner, source, dependencies)
    except asyncio.CancelledError:
        await repository.update_email(email_id, status=InboxEmailStatus.ERROR, error=SHUTDOWN_REASON)
        raise
    except Exception as pipeline_error:
        logger.exception("inbox_email_failed", email_id=email_id)
        await repository.update_email(email_id, status=InboxEmailStatus.ERROR, error=str(pipeline_error))
```

`_analyze` runs these steps in order:

1. `email = source if isinstance(source, FetchedEmail) else await mail_gateway.fetch_email(source)`
2. `update_email(sender, subject, body, received_at)`
3. Build the invoice file: `invoice_file = await _store_invoice_file(email_id, owner, email, files)`
   - If there is a PDF attachment: `files.upload(owner, attachment.filename, attachment.mime, attachment.content)`.
   - Otherwise: `files.upload(owner, f"email-{email_id}.txt", "text/plain", f"{email.subject}\n\n{email.body}".encode())`.
4. Build the guard text:
   - `pdf_text = await files.get_context(owner, [file_id]) if has_pdf else ""`
   - `guard_text = "\n\n".join(part for part in (email.subject, email.body, pdf_text) if part)`
5. `verdict = await guardrails.check(GuardrailCheckRequest(context=guard_text))`
   - `GuardrailUnavailableError` propagates to the generic handler, so the email goes to `error` with message "guardrail unavailable". Map this message explicitly.
6. If `not verdict.allowed`: `update_email(status=BLOCKED, violations=..., file_id=...)`, log `inbox_email_blocked`, and return.
7. `accepted = await payments.start_run(PaymentRunTrigger(file_id=file_id), owner)`
8. `update_email(status=ANALYZING, file_id=file_id, run_id=accepted.run_id)`, then log `inbox_email_analyzing`.

### `service.py`: `InboxService(repository, registry: ExecutionRegistry, dependencies: InboxDependencies, auth: "AuthClient", callback_url: str)`

The service reaches `mail_gateway` and `payments` through `dependencies`; it does not get them as separate parameters.

| Method | Behaviour |
|---|---|
| `start_connection(owner, provider) -> MailboxConnectStarted` | Calls `mail_gateway.link_account(owner.user_id, provider, callback_url)`, then `insert_connection(...)`. Returns `MailboxConnectStarted(connection_id, redirect_url)`. |
| `confirm_connection(owner, connected_account_id) -> MailboxConnectionView` | Calls `get_owned_connection`; `None` → `MailboxConnectionMissingError`. Then `status = await mail_gateway.get_account_status(ca_id)`. If `ACTIVE` and `trigger_id is None`, it calls `enable_new_mail_trigger` and stores the trigger id. It updates the status and returns the view. This is idempotent. |
| `list_connections(owner) -> list[MailboxConnectionView]` | |
| `ingest_webhook(body: bytes, headers: Mapping[str, str]) -> None` | Steps: `event = mail_gateway.parse_webhook(body, headers)` (may raise `WebhookSignatureError`) → `None` → return; `connection = get_connection_by_account(event.connected_account_id)` → `None` → log `inbox_webhook_unknown_account` and return; `owner = await auth.get_user(connection.owner_id)`; `email_id = insert_email(connection.owner_id, event.provider, event.message_id, connection.connection_id)` → `None` → log `inbox_webhook_duplicate` and return; `registry.spawn(email_id, process_email(email_id, owner, event, dependencies))`. |
| `simulate(owner, kind) -> InboxEmailView` | `email_id = insert_email(owner.user_id, MailProvider.SIMULATED, f"sim-{uuid4()}")`, then spawn with `SIMULATED_EMAILS[kind]`. Returns the current view. |
| `list_emails(owner) -> list[InboxEmailView]` | `[await self._to_view(owner, record) for record in await repository.list_emails(owner.user_id)]` |
| `get_email(owner, email_id) -> InboxEmailDetail` | `None` → `EmailMissingError`. |
| `fail_unfinished(reason)` / `shutdown()` | Mirror `PaymentsService`. |

`_to_view` derives the displayed status:

```python
async def _resolve_status(self, owner, record) -> tuple[InboxEmailStatus, InvoiceClpAnalysis | None, str | None]:
    if record.status != InboxEmailStatus.ANALYZING or record.run_id is None:
        return record.status, None, record.error
    run = await self._dependencies.payments.get_run(record.run_id, owner)
    if run.status == RunStatus.COMPLETED:
        is_invoice = run.analysis is not None and run.analysis.is_invoice
        return (InboxEmailStatus.ANALYZED if is_invoice else InboxEmailStatus.NO_INVOICE), run.analysis, None
    if run.status == RunStatus.FAILED:
        parse_failed = any(event.step == "invoice_parse_failed" for event in run.events)
        return (InboxEmailStatus.NO_INVOICE if parse_failed else InboxEmailStatus.ERROR), None, run.error
    return InboxEmailStatus.ANALYZING, None, None
```

`preview` is `" ".join(record.body.split())[:140]`.

## Integration Notes

- The owner check is everywhere: repository methods filter by `owner_id`, and webhooks resolve the owner only through `mailbox_connections`.
- The inbox never imports `modules.payments`, `modules.guardrails` or `modules.mail_gateway`. It uses only their clients, plus their `contracts.*` types.
- Router-facing methods return only `ApiModel` views.
