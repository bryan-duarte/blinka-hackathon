# SSM Config Implementation

## Overview

Every backend env var is stored as an SSM parameter at `/blinka/prod/<ENV_VAR_NAME>`. There are two groups. **managed** values are owned by Terraform. **operator** values are seeded once, then left for a human to change in the console. The JWT and demo secrets are generated by Terraform. The Lambda authorizer gets the same JWT secret.

## Files to Modify/Create

- `infra/ssm.tf` (new) contains:
  - `random_password.jwt_secret` and `random_password.demo_password`
  - `locals { managed_params, operator_params, backend_params }`
  - `aws_ssm_parameter.managed` and `aws_ssm_parameter.operator`
- `infra/realtime.tf:47`: change `JWT_SECRET = var.jwt_secret` to `JWT_SECRET = random_password.jwt_secret.result`.
- `infra/variables.tf`:
  - Delete `variable "jwt_secret"` (lines 37-41).
  - Add `frontend_origin` (string, required, description "Vercel origin, e.g. https://blinka.vercel.app — no trailing slash").

## Implementation Guidelines

```hcl
resource "random_password" "jwt_secret" {
  length  = 64
  special = false
}

resource "random_password" "demo_password" {
  length  = 20
  special = false

resource "aws_ssm_parameter" "managed" {
  for_each = local.managed_params
  name     = "${local.ssm_prefix}/${each.key}"
  type     = each.value.secure ? "SecureString" : "String"
  value    = each.value.value
}

resource "aws_ssm_parameter" "operator" {
  for_each = local.operator_params
  name     = "${local.ssm_prefix}/${each.key}"
  type     = each.value.secure ? "SecureString" : "String"
  value    = each.value.value

  lifecycle {
    ignore_changes = [value]
  }
}

locals {
  # Consumed by the task definition's `secrets` block (module 06).
  backend_params = merge(aws_ssm_parameter.managed, aws_ssm_parameter.operator)
}
```

Notes:
- **Sensitive values in `for_each`.** `for_each` cannot iterate over a map whose values are sensitive (`random_password.result`). Because the map keys are static strings, Terraform normally accepts it. If plan fails with "Sensitive values ... for_each", wrap the expression as `for_each = nonsensitive(toset(keys(local.managed_params)))` and read values with `local.managed_params[each.key]`.
- **Parameter tier.** Use the Standard tier (free). Every value fits under 4 KB.
- **AWS profile.** Don't create any `*_AWS_PROFILE` parameter (see module 01).

## Integration Notes

- **Contract with module 06.** `local.backend_params` is a map of `ENV_VAR_NAME => aws_ssm_parameter`. The task definition maps it as follows:
  ```hcl
  secrets = [for name, param in local.backend_params : { name = name, valueFrom = param.arn }]
  ```
- **Outputs (module 06 `outputs.tf`).** Add `jwt_secret = random_password.jwt_secret.result` and `demo_password = random_password.demo_password.result`. Mark both `sensitive = true`.
- **Side effect of the JWT change.** Changing the authorizer Lambda's `JWT_SECRET` is an in-place update, and it rotates the realtime auth secret for local dev as well.
